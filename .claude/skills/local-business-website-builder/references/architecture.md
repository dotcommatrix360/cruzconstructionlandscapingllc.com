# Architecture & Organization

Agency standard since v2.0.0: **every new website is an Astro project with static output.** Legacy hand-built HTML
repos (v1) keep their structure until a migration is approved — see "Legacy static repos" at the end.

## Astro project layout

```
/                               ← repo root = source only (never served)
├── astro.config.mjs            ← site URL from site.config.json, output 'static', trailingSlash 'always', directory format
├── site.config.json            ← business facts, nav, CTA, integrations, redirects, hosting (single source of truth)
├── package.json  package-lock.json  .node-version (22.22.0+)  tsconfig.json  .gitignore
├── integrations/hosting-files.mjs   ← writes sitemap.xml, robots.txt, _redirects, .htaccess redirects into dist/
├── public/                     ← copied to dist/ as-is: .htaccess, _headers, favicon.svg, logo.svg, og-default.jpg
├── src/
│   ├── pages/                  ← routes: index.astro, contact.astro, 404.astro, services/, service-areas/, blog/, [...permalink].astro
│   ├── layouts/                ← BaseLayout (document) + ServiceLayout, LocationLayout, PostLayout
│   ├── components/             ← Seo, JsonLd, Tracking, Header, Footer, Hero, CtaBand, FaqList, ServiceCards,
│   │                             Testimonials, Breadcrumbs, ContactForm, ResponsiveImage
│   ├── content/                ← blog/*.md, services/*.md, locations/*.md, testimonials/testimonials.json
│   ├── content.config.ts       ← collection schemas (zod) — SEO minimums enforced at build time
│   ├── lib/                    ← site.ts (typed config), schema.ts (JSON-LD), content.ts (URLs, sorting)
│   ├── styles/                 ← tokens.css (all design values) + global.css (base, primitives, shared components)
│   └── assets/images/          ← original photos (one master each); Astro generates AVIF/WebP sizes
├── .github/workflows/          ← quality.yml (checks on push) + deploy-production.yml (MANUAL production deploy)
├── CLAUDE.md                   ← client notes + agency rules for future sessions
└── .claude/skills/local-business-website-builder/   ← vendored skill (never published)

dist/   ← generated by `npm run build`; uploaded to hosts; NEVER committed (in .gitignore)
```

Only `dist/` is ever published. Source files can't leak because they are never uploaded — `check-protection.mjs`
still scans `dist/` for anything that shouldn't be there (env files, Markdown sources, configs, source maps).

### Why these choices

| Choice | Reason |
|---|---|
| `output: 'static'`, no adapter | Every page is pre-rendered HTML: fastest, cheapest, most secure, crawlable without JS; works on any host |
| `trailingSlash: 'always'` + `build.format: 'directory'` | `/about/` → `about/index.html`: identical URLs on Hostinger, WP Engine and Cloudflare; matches typical WordPress URLs |
| Exact version pins + `package-lock.json` | Staging (Cloudflare) and production (GitHub Actions) build byte-identical sites |
| `site.config.json` (not `.env`) for facts | Business facts are public data and must be reviewable in git; secrets never go here |
| Local integration for sitemap/redirects | One redirect list → both host formats; sitemap that honours noindex + canonical; build fails on unsafe redirects |
| Content collections + one layout per type | No copy-pasted page variants; schemas stop thin or incomplete pages at build time |

## Naming

- Files/folders: lowercase kebab-case, descriptive (`roof-repair.md`, `team-jane-doe.jpg`). Content file name = URL slug.
- URLs: `/services/roof-repair/` — short, readable, stable, trailing slash. Keep old URLs with `permalink:` during migrations.
- Components: PascalCase `.astro`; one responsibility each; props typed with `interface Props`.
- CSS: tokens in `tokens.css`; shared classes in `global.css` (`.container`, `.section`, `.grid`, `.card`, `.btn--primary`, `.prose`); everything else scoped inside the component.

## Pages, layouts and components

- Every page renders through `BaseLayout`, passing `title`, `description` and optional `image`, `noindex`, `type`. `Seo.astro` then emits title (brand suffix only while ≤ 60 chars), description, canonical (production URL of this page), robots, Open Graph — they can't be forgotten.
- Structured data: `<JsonLd slot="head" data={…} />` with builders from `src/lib/schema.ts` (LocalBusiness on home/contact, Service, BreadcrumbList via `Breadcrumbs`, BlogPosting, FAQPage via `FaqList`). Builders drop empty fields; they never invent values.
- One `<h1>` per page, usually in `Hero`. Component headings take a `headingLevel` prop so the outline stays correct wherever they're used.
- The inline `document.documentElement.classList.add('js')` in `BaseLayout` must stay inline (before paint) — moving it into a bundle causes layout shift of the mobile menu.
- Client-side JS: `<script>` inside a component (Astro bundles, dedupes and defers it). Keep each under ~150 lines; progressive enhancement only.
- Islands (React/Vue/Svelte via `client:*`) only for substantial interactivity — calculators with complex state, booking flows — and only after checking a hosted embed or a small vanilla script won't do. Record the reason in `CLAUDE.md`.

## site.config.json

`site` (url, name, language, locale, titleSuffix, defaultOgImage) · `business` (type, NAP, geo, hours, areaServed, sameAs, licenses — **only real values**) · `nav` · `cta` · `blog` (title, description, perPage) · `integrations` (GTM/GA4/Clarity IDs, form provider + endpoint) · `redirects` ([{from, to, status}]) · `deploy` (production host + domain, staging project/url). Components read it through `src/lib/site.ts`; scripts read it too (validate, migration-check, deploy-settings).

## Styling

- `tokens.css` is the only place colors, type scale, spacing, radii, shadows and motion are defined — replace every value per client.
- Fluid type/spacing with `clamp()`, logical properties, `:focus-visible`, `prefers-reduced-motion`. No `!important` except utilities.
- Self-host fonts (woff2 in `public/fonts/` or via a pinned `@fontsource/*` package) — 1–2 families, ≤ 4 files.

## Caching & versioning

Astro fingerprints everything it emits into `dist/_astro/` (file names change with content), so the starter `.htaccess`
and `_headers` cache those for a year; HTML is `no-cache`. Files in `public/` keep their names — rename when they change.

## Custom 404

`src/pages/404.astro` → `dist/404.html` (noindex, helpful links). Hostinger: `ErrorDocument 404 /404.html`; Cloudflare
Pages serves it with HTTP 404 automatically (without it, every unknown URL returns the homepage with 200).

## When to go beyond static Astro

| Need | Reasonable choice |
|---|---|
| Client edits content weekly without a developer | Git-based CMS writing the same Markdown (Decap CMS, Pages CMS, Keystatic) — the site stays static |
| Ecommerce | Shopify / platform checkout, linked or embedded |
| Forms, booking, logic | Hosted form/GHL/booking embeds; a serverless function only if truly needed |
| Hundreds of records with filtering | Still static Astro + a generated JSON index and a small client-side filter |

Record the reason in `CLAUDE.md`.

## Legacy static repos (v1, maintenance only)

Hand-written HTML at the repo root, made maintainable by the zero-dependency `build.mjs`:

- `_partials/*.html` injected between `<!-- @include name -->` and `<!-- @endinclude -->` markers; built-ins `schema:localbusiness`, `meta:robots`.
- `_content/<collection>/*.md` + `_templates/*.html` → generated article, archive, pagination, category pages (`references/content-collections.md`, legacy section).
- `site.config.json` → facts, `collections`, integrations, deploy. Build adds `aria-current`, `?v=hash`, `sitemap.xml`, removes stale generated pages.
- Web root = repo root, served by Cloudflare (`exit 0`, output `/`) and Hostinger (owner's manual Redeploy). Dev files hidden by `.htaccess` AND `_redirects`.

All QA scripts still work on these repos (they detect the project type). `init.mjs --legacy-static [--only …]` adds
pieces to an existing HTML repo. New sites never use this layout; migrating a legacy site to Astro is a separate,
approved project (`references/migrations.md`, "HTML → Astro").
